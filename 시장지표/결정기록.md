# 결정기록 — 시장지표

지금 코드가 왜 이렇게 동작하는지 설명하는 운영 결정. 코드 주석에서 옮겼다(2026-10-25 주석 정리). 실험 경위·수치는 CLAUDE.md에 있다.

## KOSPI·KOSDAQ는 ECOS에서 받고 코드명은 유지
- 결정: KOSPI·KOSDAQ 일별 종가는 ECOS 802Y001(항목 0001000·0089000)에서 받는다. 코드명은 `ECOS_<통계표>_<항목>` 규칙의 예외로 "KOSPI"·"KOSDAQ" 그대로 둔다.
- 이유: FDR이 지수(KS11·KQ11)를 읽는 GitHub 캐시가 2026-09-17 장중 스냅숏 이후 갱신을 멈춰, 0건 적재가 조용히 이어졌다. 피처 컬럼명·신선도 점검·KOSPI 수익률 계산이 이 이름을 키로 쓰므로 이름을 바꾸면 학습 피처가 바뀐다.
- 관련 코드: 지표_공통.ECOS_INDICATOR_META, feature_loader.INDICATOR_CODES
- 결정 시점: 2026-10-03

## 일별 지표 신선도 점검과 종료 코드
- 결정: 증분 적재가 모두 커밋된 뒤, 일별 지표 6종마다 최신일이 daily_stock_prices 최신 거래일보다 몇 거래일 뒤처졌는지(lag)를 센다. 휴장일은 주가 날짜에 없으므로 세지 않는다. lag 1 이상은 경고, 한도 이상은 실패다. 실패·지표 적재 실패·섹션 전체 실패가 있으면 exit 1.
  - 한도: KOSPI·KOSDAQ·국고채 3/10년 2, USD_KRW 3, 기준금리 4. 월별 지표는 대상이 아니다.
  - 한도 = 구조적 공백 + 공표 지연 허용 + 1. 구조적 공백은 2025-09~2026-09 255거래일 실측으로 일별 ECOS 0, USD_KRW 1(Yahoo가 금요일 세션을 일요일 날짜로 붙임).
  - 기준금리는 ECOS 공개가 보통 2일(달력) 늦고 가끔 며칠치를 한 번에 따라잡아, 수~금에는 lag 2가 정상이다. 그래서 공표 지연 2 + 1 = 3까지 정상, 4부터 실패로 둔다. 금통위 날에만 바뀌는 계단형 값이라 며칠 늦어도 피처 영향은 작다.
- 이유: 소스가 빈 결과를 돌려줘도 증분 적재는 "0건 적재"로 정상 종료해, FDR 지수 캐시가 멈춘 9거래일 동안 Actions가 성공으로 보였다. 판정을 모든 저장 뒤로 미뤄 한 지표의 문제가 다른 지표 저장을 막지 않게 한다. 기준금리 한도 2는 정상 지연을 실패로 판정했고, 그 실패를 보고 장중에 수동 재실행한 것이 10/08 잠정값 저장 사고의 발단이었다.
- 한계: 기준일이 주가 최신일이라 주가 수집도 함께 멈추면 뒤처짐이 드러나지 않는다.
- 관련 코드: 지표_공통.DAILY_LAG_LIMITS, 지표_공통.check_daily_indicator_lag, 지표_일일수집.run_incremental
- 결정 시점: 점검 2026-10-03, 기준금리 한도 4 2026-10-10

## 월별 지표의 published_date
- 결정: ECOS 월별 지표(CPI·M2·선행지수)는 date = 기준월 1일, published_date = 기준월 다음 달 말일로 저장한다. 일별 지표는 published_date = date.
- 이유: 실제 공표일을 소스에서 받을 수 없어 보수적인 날짜를 쓴다.
- 한계: M2(161Y005)는 실제로 기준월 + 2개월 중순에 발표돼 저장일이 13~16일 이르다 — 과거 학습·검증 피처에 미공개 값이 쓰였다(미조치, CLAUDE.md 알려진 이슈).
- 관련 코드: 지표_공통.parse_ecos_records, 지표_공통._next_month_end

## 개정값은 최신값만 유지하고 신규·개정 건수를 센다
- 결정: market_indicators는 `ON CONFLICT DO UPDATE ... WHERE value IS DISTINCT FROM EXCLUDED.value`로 값이 다를 때만 value·published_date를 바꾸고, `RETURNING (xmax <> 0)`로 신규와 개정을 구분해 센다. 이력은 남기지 않는다. 메타(indicator_meta)는 지표 행보다 먼저 upsert한다(FK).
- 이유: 테이블 사용 계약(CLAUDE.md "market_indicators 사용 계약")을 한 곳에서 지킨다. 같은 값을 다시 받아도 행이 바뀌지 않는다.
- 관련 코드: db_utils.upsert_market_indicators, db_utils.upsert_indicator_meta

## 확정 컷오프와 강제 재수집
- 결정: USD_KRW는 `constants.CLOSE_FINAL_CUTOFF_KST`(19:40) 전 KST 오늘 행을 저장하지 않는다(증분·--force). 이미 저장된 날짜의 정정은 `--force --start [--end] [--codes] [--dry-run]`으로만 하고, 범위로 조회한 뒤 날짜로 거른다. 소스에 없는 DB 행은 지우지 않는다.
- 이유: 장중 값은 잠정값이다. Yahoo USD/KRW는 하루치(D, D) 조회에 D가 아닌 앞선 날 봉을 돌려준다.
- 관련 코드: 지표_공통.fetch_fdr_indicator_data, 지표_공통._fetch_indicator_range, 지표_공통.force_refetch_indicator
- 결정 시점: --force 2026-09-27, 컷오프 2026-10-10

## 지표는 published_date < 거래일로만 붙인다
- 결정: 거래일 D의 피처 행에는 published_date < D인 지표 값 중 최신값만 붙인다(`merge_asof(direction="backward", allow_exact_matches=False)`). 같은 날 공표분은 붙지 않는다.
- 이유: 공표 시각을 모르므로 같은 날 값은 장중 이후 정보일 수 있다(미래 정보 누수).
- 관련 코드: feature_loader._asof_join, feature_loader.get_features

## 가격·지표는 실행당 한 번 읽어 캐시로 공유
- 결정: 학습·예측은 지표 9종(load_indicator_cache)과 종목 가격(load_price_cache, `ticker = ANY` 한 번)을 실행 시작에 한 번 읽어 공유한다. 지표 조회 하한은 "시작일 이전 마지막 공표일"이라 결과가 전체 조회와 같다. 캐시에는 구간을 attrs로 남겨, 다른 구간에 쓰면 예외를 낸다(end_date 일치는 호출자 책임).
- 이유: 종목마다 지표 전체 이력을 두 번씩 읽어 Neon 무료 전송량을 다 썼다. 구 경로와 데이터셋·예측이 비트 단위로 같음을 확인했다.
- 관련 코드: feature_loader.load_indicator_cache, feature_loader.load_price_cache, feature_loader._load_indicator_series
- 결정 시점: 지표 캐시 2026-09-20, 하한·가격 캐시 2026-10-05

## ECOS 오류 메시지에서 API 키를 뺀다
- 결정: ECOS 요청 예외는 클래스명과 요청 식별자만 담은 RuntimeError로 바꿔 다시 던지고(원 예외는 붙이지 않음), 출력하는 예외 메시지는 config.redact로 비밀값을 가린다.
- 이유: ECOS는 키를 URL 경로에 넣고, requests 예외 문자열에는 URL이 들어간다(가짜 키로 재현).
- 관련 코드: 지표_공통.fetch_ecos_series, 지표_공통.load_ecos_indicators, 지표_일일수집.run_force
- 결정 시점: 2026-10-11
