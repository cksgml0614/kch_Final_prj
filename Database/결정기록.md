# 결정기록 — Database(테이블·뷰 정의 SQL)

지금 스키마가 왜 이렇게 생겼는지 설명하는 결정과 운영 DB에 적용한 마이그레이션 이력. SQL 파일 주석에서 옮겼다(2026-10-25 주석 정리, SQL 문 자체는 바꾸지 않았다). 마이그레이션 SQL은 원문 그대로 옮겼고 모두 운영 DB에 적용이 끝났다 — 다시 실행하지 않는다.

## 테이블_생성.sql이 지금 스키마의 정본
- 결정: `Database/{도메인}/테이블_생성.sql`은 운영 DB의 지금 스키마를 그대로 재현한다. 스키마를 바꿀 때는 운영 DB에 ALTER TABLE로 적용하고 같은 내용을 이 파일에 반영한다. 옛 `Database/migrations/` 방식은 쓰지 않는다. 기존 테이블을 DROP하지 않는다.
- 이유: 2026-08-23에 운영 DB를 information_schema·pg_constraint·pg_indexes로 조회해 다시 썼고, 격리된 임시 스키마에 재생성해 컬럼·제약·인덱스까지 일치를 확인했다. 파일 하나만 보면 스키마를 알 수 있게 한다.
- 관련 코드: Database/*/테이블_생성.sql
- 결정 시점: 2026-08-23

## market_indicators 적재·삭제 순서와 FK
- 결정: FK `fk_market_indicators_meta`는 ON UPDATE CASCADE, ON DELETE RESTRICT. 적재는 indicator_meta → market_indicators, 삭제는 market_indicators → indicator_meta. published_date는 DEFAULT 없이 코드에서 명시 대입한다. market_indicators.unit은 DEPRECATED(항상 NULL, indicator_meta.unit 사용).
- 이유: 메타 한 줄 삭제로 지표 값이 조용히 사라지는 사고를 막는다. 코드명 변경은 메타만 UPDATE하면 자식이 따라온다. published_date 누락은 INSERT에서 바로 실패해야 누수 없는 피처 조회(published_date < 거래일)가 보장된다.
- 관련 코드: Database/시장지표/테이블_생성.sql, 시장지표 수집기
- 결정 시점: 2026-08 (Task G-1)

## model_predictions는 변동성 예측 전용, baseline·게이트를 함께 저장
- 결정: model_predictions는 다음 거래일 변동성 예측(predicted_volatility)을 저장하고, 같은 시점 baseline 3종(GARCH·SMA20·Parkinson-SMA20)과 게이트 판정(종합 + baseline별)을 같은 행에 남긴다. 옛 방향 예측 스키마(predicted_return 기반)는 대체했다.
- 이유: 배포 게이트가 "하이브리드가 baseline 셋을 모두 이겨야 통과"로 정의돼 있어, 매 예측 시점의 값을 나란히 남겨야 사후에 판정 근거를 감사할 수 있다. 방향 예측은 무작위 수준이라 폐기했다.
- 관련 코드: Database/가격예측/테이블_생성.sql, 가격예측.store.save_prediction, 가격예측.evaluate.passes_deployment_gate_volatility
- 결정 시점: 2026-09-06(변동성 전환), 2026-09-07(Parkinson-SMA20 포함)

## is_early_warning은 기록용 값
- 결정: is_early_warning = 예측 σ > 직전 60일 예측 σ 평균의 1.5배를 그대로 저장한다. 운영 신호로 쓰지 않는다.
- 이유: 이 규칙의 조기경보 능력은 원 검증이 GARCH 라벨링 버그로 무효화된 뒤 재검증에서 우연 수준으로 확인됐다.
- 관련 코드: 가격예측.store(is_early_warning 계산)
- 결정 시점: 2026-09-06

## 게이트 미통과여도 저장하고 trusted 뷰로 거른다
- 결정: model_predictions에는 게이트 통과 여부와 무관하게 항상 저장하고, model_predictions_trusted 뷰(`gate_passed AND NOT input_data_suspect`)로 신뢰 가능한 행만 본다. 새 테이블은 만들지 않는다.
- 이유: 미통과 시 저장을 건너뛰던 방식(A-1, 2026-09-12)은 게이트가 연속 미통과하는 동안 실측과 대조할 예측이 쌓이지 않았다. 조회할 때마다 조건을 기억해야 하는 부담을 뷰로 줄인다. input_data_suspect는 지수 결측만 보므로 장중 잠정값으로 만든 예측도 trusted에 들어갈 수 있다(2026-10-08 사고).
- 관련 코드: Database/가격예측/뷰_생성.sql
- 결정 시점: 2026-09-14(D-1), 2026-09-27(input_data_suspect 조건 추가)

## 실측은 target_date가 아니라 prediction_date 뒤 첫 거래일로 계산
- 결정: model_predictions_realized 뷰는 prediction_date 뒤 그 종목의 첫 거래일로 실측(realized_volatility)을 계산하고 realized_date·realized_status·target_halted를 붙인다. actual_volatility 컬럼은 옛 백필 스냅숏으로 남기고 더 채우지 않는다.
- 이유: next_weekday()가 공휴일을 몰라 target_date가 휴장일(8/17·9/24·10/5·10/9, 400행)이면 actual_volatility가 영구 NULL이었다. 백필 스크립트는 2026-10-17 정리에서 지웠다. 기존 actual_volatility 2,002행과 뷰 값은 불일치 0이었다. close <= 0 행은 ln 오류 대신 NULL로 둔다. 뷰는 p.*라 model_predictions에 컬럼을 추가하면 DROP 후 다시 만들어야 한다.
- 관련 코드: Database/가격예측/뷰_생성.sql, 대시보드.백테스트_재생(같은 정의를 코드로 옮김)
- 결정 시점: 2026-10-11

## model_registry에 FK를 걸지 않는다
- 결정: model_registry(모델 버전마다 1행)와 model_predictions 사이에 FK를 두지 않는다. 새 version은 store.register_model_version이 체크포인트 저장 직후 INSERT ... ON CONFLICT DO NOTHING으로 등록한다(source 'live', gate_definition 'tickermean'). hyperparameter_ref 컬럼은 쓰지 않는다(튜닝값은 MLflow param tuned_params_id와 체크포인트 extra_meta).
- 이유: 등록은 부가 기록이라 실패해도([REGISTRY-SKIP]) 예측 저장은 계속돼야 한다. 처음 설계 때는 일일 파이프라인이 registry 등록 전에 model_predictions에 써서 FK가 있으면 저장이 실패했다.
- 관련 코드: Database/가격예측/테이블_생성.sql, 가격예측.store.register_model_version
- 결정 시점: 2026-10-11(테이블·자동 등록)
- 최초 적재 규칙(2026-10-11, 54행): 체크포인트 meta 53개(family_basis='checkpoint_meta') + 20260914_132800 1행(체크포인트 없음, 'inferred'). source: n_train < 10000 → 'test', saved_at 2026-09-14 13:39~15:02 UTC이면서 train_end < 2026-09-14 → 'backtest_d4_20260914', 나머지 → 'live'. gate_definition: version < 20260928_085818 → 'pooled', 이후 → 'tickermean'.

### 2026-09-07 — parkinson_sma20_baseline·gate_vs_parkinson 추가
실제로는 2026-09-12에 model_predictions에 행이 없어 `테이블_삭제.sql` → `테이블_생성.sql`로 다시 만들어 반영했다(아래 ALTER는 그때 쓰지 않았다).

```sql
ALTER TABLE model_predictions
    ADD COLUMN IF NOT EXISTS parkinson_sma20_baseline NUMERIC,
    ADD COLUMN IF NOT EXISTS gate_vs_parkinson BOOLEAN;
-- 기존 행이 있으면 백필 후 NOT NULL을 건다.
ALTER TABLE model_predictions
    ALTER COLUMN parkinson_sma20_baseline SET NOT NULL,
    ALTER COLUMN gate_vs_parkinson SET NOT NULL;
```

### 2026-09-27 — input_data_suspect 추가
배경: FDR 지수 캐시가 2026-09-17 장중 스냅숏 이후 갱신되지 않아 KOSPI/KOSDAQ가 9/18부터 결측이었다. 그 상태로 만든 예측(prediction_date 9/18·9/23, 200행)은 KOSPI 레벨 피처가 forward-fill되고 excess_return_z_lag1이 KOSPI 수익률 0으로 계산된 오염 입력을 썼다. 소급 재계산하지 않고(기록 보존) 이 플래그로 표시한다. 이후 실행은 가격예측_변동성_공통.check_market_index_freshness()가 결측을 감지하면 true를 기록한다. ALTER로 맨 뒤(created_at 다음)에 붙었으므로 테이블_생성.sql도 같은 위치에 둔다. 같은 날 9/14 주가 장중 수집 오염(84종목 종가, --force로 정정)을 쓴 예측 2행도 표시했다.

```sql
ALTER TABLE model_predictions ADD COLUMN IF NOT EXISTS input_data_suspect BOOLEAN NOT NULL DEFAULT false;
UPDATE model_predictions SET input_data_suspect = true WHERE prediction_date IN ('2026-09-18', '2026-09-23');
UPDATE model_predictions SET input_data_suspect = true WHERE prediction_date = '2026-09-14';
```
