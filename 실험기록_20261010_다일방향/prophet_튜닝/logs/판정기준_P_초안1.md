# 판정기준_P — Prophet 튜닝 후속 실험 (초안, 미고정)

상태: **초안**. 사람 승인 후 sha256을 `판정기준_P.sha256`에 고정하고, 이 실험의 첫 Prophet fit 전까지만 개정할 수 있다
(개정마다 사유와 전후 해시를 9절에 기록). 첫 fit 이후 변경 금지. 상위 실험의 판정기준(`../판정기준.md`, 개정 2,
sha256 `bf22c24e…2849ad`)은 바꾸지 않으며, 모든 스크립트는 두 해시를 시작 시 확인한다.

**이 실험은 1번 실험(다일 방향 예측)의 결론 "신호 없음"을 바꾸지 않는다.** 1번 실험의 판정 대상은 LSTM이었고, 이
실험은 Prophet만 다루는 별개의 질문이다.
**마지막 12개월 holdout(2025-10-10 이후)은 이 실험으로 소진된다.** 이후 어떤 실험도 이 구간을 미개봉 평가 구간으로
쓸 수 없다.

## 1. 범위
- 대상: Prophet만. LSTM은 제외한다.
- 데이터: 기존 `../data/prices.parquet`, `../data/kospi.parquet`만 쓴다. Neon 읽기·쓰기 없음.
- 작업 위치: `실험_20261010_다일방향/prophet_튜닝/` 하위만. Prophet 실행은 상위 폴더의 전용 venv(`../.venv_prophet`).
- 유니버스·라벨·피처 정의·격자·기업 행동 필터는 상위 판정기준(1~4절)과 같다. 라벨 6조합 = h {3, 7, 30} × {절대, 초과}.

## 2. 설정 후보 (12개, 사전 선언. 목록에 없는 설정은 나중에 추가 금지)
- changepoint_prior_scale ∈ {0.01, 0.05, 0.2, 0.5} × 학습 이력 길이 ∈ {250, 500, 전체} 거래일.
- 이력 길이 n: 앵커 t를 포함한 그 종목(또는 KOSPI)의 마지막 n거래일. "전체" = 2020-01-02부터. 이력이 n보다 짧으면
  있는 만큼 쓴다(행 수를 기록).
- 고정: weekly·yearly·daily 계절성 끔, 나머지 Prophet 기본값. 예측 수익률 = exp(예측 log 종가[t+h]) / 실제 종가[t] − 1,
  초과 라벨 점수 = 종목 예측 수익률 − 같은 앵커·같은 설정 KOSPI 예측 수익률. 앵커마다 재적합.
- 기본 설정 = (0.05, 전체). 1번 실험 ③과 같다.

## 3. 설정 선택 (개발 구간 앞쪽만)
- 선택 표본: 상위 실험 walk-forward의 평가 덩어리 k0~k5(앵커 2022-01-03~2024-12-30)의 격자 행.
- 선택 지표: **h=3·h=7의 4조합(절대·초과) AUC 단순 평균**이 가장 높은 설정 하나. h=30은 선택 표본의 독립 날짜가
  약 23개라 선택 지표에서 뺀다(보고는 함). 고른 설정 하나를 6조합 모두에 쓴다.
- 동률(평균 AUC 차이 < 0.0005)이면 이력 "전체"를 우선하고, 그다음 changepoint_prior_scale이 0.05에 가까운 쪽을 고른다.
- 12개 설정 전체의 선택 표본 결과(조합별 AUC·IC)를 표로 남긴다.
- 공개 사항: 기본 설정의 이 표본 성능은 1번 실험 단계 ②에서 이미 관측됐다(선택 기준은 그 뒤에, 다른 설정 결과를 보기
  전에 정한 것).
- 참고 보고(판정에 쓰지 않음): 선택 후 holdout 전에, 선택에 쓰지 않은 개발 덩어리 k6~k7(2025-01-02~2025-09)에서 선택 설정과
  기본 설정의 AUC·IC를 보고한다.

## 4. holdout 평가 (단 한 번)
- 구간: 앵커 t ≥ 2025-10-10, 라벨 끝 t+h ≤ 2026-10-08. 격자 = holdout 첫 거래일부터 h거래일 간격.
- 독립 평가 날짜 수(추정, 12개월 약 245거래일 기준): **h=3 약 81, h=7 약 34, h=30 약 8.** 정확한 값은 holdout 라벨을
  열기 전, 날짜만으로 계산해 로그에 남긴다.
- 비교 후보(같은 표본): 선택 설정 Prophet, 기본 설정 Prophet, ① 다수 클래스(학습 = 2025-10-10 이전 개발 구간 전체의
  다수 방향), ② 과거 30·60·120일 수익률 부호.
- 열람 기록: holdout 평가 스크립트는 시작할 때 `logs/holdout_opened.log`가 있으면 중단하고, 없으면 시각·선택 설정·두 해시를
  먼저 쓴 뒤 라벨을 읽는다. 결과가 나빠도 재튜닝·재평가하지 않는다.

## 5. "신호 있음" 판정 (holdout, 조합별, 아래를 전부 충족)
- 판정 대상 호라이즌: holdout 독립 평가 날짜가 **30개 이상**인 호라이즌만(추정상 h=3·h=7, 4조합).
  30개 미만(추정상 h=30)은 **"판정 불가"**로 적고, 지표는 기술 통계로만 싣는다.
- 다중비교 보정: 설정 12개 × 판정 조합 4개 = 48로 본페로니 보정해 **99.9% 신뢰구간**(양측 α ≈ 0.001)을 쓴다.
  부트스트랩은 holdout 격자 날짜 블록(블록 = ceil(20/h) 격자 단위, ≥ h거래일), B = 20,000, 백분위 구간.
1. AUC(선택 설정) − AUC(①② 중 같은 표본 최고)의 99.9% CI 하한 > 0.
2. 선택 설정 IC 평균(날짜별 Spearman)의 99.9% CI 하한 > 0.
3. 분기 일관성: holdout을 앵커 날짜 기준 4개 분기로 나눠, AUC 차이 > 0 이고 IC 평균 > 0 인 분기가 3개 이상.
- 하나라도 실패하면 그 조합은 "신호 없음". 선택 설정 − 기본 설정 AUC 차이(99.9% CI)는 함께 싣되 판정에 쓰지 않는다.
- 레이블 셔플 귀무는 이 실험에 포함하지 않는다.

## 6. 예상 소요와 PC 부하
- fit 시간 근거: 1번 실험 실측(전체 이력, 12프로세스) 초당 37.1회. 짧은 이력의 속도는 미측정이라 같은 속도를 상한으로 쓴다.
- 선택 단계: 앵커 날짜(h=3·h=7 격자 합집합, k0~k5) 약 315개 × 시계열 약 99개(종목 + KOSPI) ≈ 설정당 약 3.1만 회.
  12개 설정 ≈ 37만 회 → **약 2.8시간 이하**. 기본 설정도 같은 코드로 다시 계산하고, 1번 실험 ③ 값과 일치하는지 확인한다.
- 참고 보고(k6~k7): 선택 설정 약 78일 × 99 ≈ 7,700회(약 4분).
- holdout: 앵커 날짜 약 103개 × 99 ≈ 설정당 약 1만 회. 선택·기본 2개 설정 → 약 2만 회(약 10분).
- 합계 약 3시간 이하. 시작 3분 뒤 처리량을 보고하고, 추정의 1.5배(4.5시간)를 넘을 것 같으면 중단하고 보고한다.
- 부하: CPU 12프로세스(논리 코어 24개의 절반), 메모리 약 3~4GB, GPU 미사용. 05:00 "Daily Pipeline"과 겹치지 않게
  시작 시각을 잡는다(겹치면 둘 다 느려질 뿐이지만 피한다). 실행 중 시스템 절전 방지(SetThreadExecutionState), 체크포인트는
  (설정, 종목, 앵커 50개 묶음) 단위로 원자적 저장, 재실행 시 이어서 계산한다.

## 7. 단계와 정지 지점
① 설정 12개 선택 단계 계산과 선택 결과 → 정지·보고 → ② k6~k7 참고 보고 → 정지·보고 → ③ holdout 단 한 번 평가와 판정 → 정지·보고.

## 8. 최종 보고서 필수 기재
- 이 실험이 1번 실험의 "신호 없음"을 바꾸지 않는다는 점, holdout이 소진됐다는 점.
- 선택 지표에서 h=30을 뺀 이유와 h=30 "판정 불가"(검정력 부족, 신호 부재의 증명 아님).
- 생존 편향(현재 유니버스) — 상위 판정기준 6-1 (b)와 같다.
- 기본 설정의 선택 표본 성능을 미리 본 상태에서 선택 기준을 정했다는 공개 사항.
